The problem

Every grant program has the same bottleneck.

A human reviewer must read the milestone evidence and decide whether the work meets the criteria before funds move. That review is slow, inconsistent between reviewers, and leaves no auditable record of why a decision was made. It is exactly the kind of judgement call an intelligent contract can settle instead.

How it works

Four stages, fully onchain.

Each stage is a contract call with enforced permissions. Nothing depends on a reviewer being available or acting in good faith.

Consensus

The validator does not trust the leader.

GenLayer's Equivalence Principle lets a contract run non-deterministic work and still reach agreement. VeriGrant uses it properly: the validator re-does the work rather than rubber-stamping a result.

leader_fn Fetch and judge

Fetches the evidence URL, prompts the LLM with the stated criteria, and returns a structured verdict containing a binary accepted field and a confidence score.

validator_fn Re-fetch and re-judge

Independently fetches the same evidence and runs its own judgement. It compares decision fields rather than free-text reasoning, so LLM wording drift is tolerated but a flipped decision is not.

✓
Welfare releases only on agreement Both must return the same binary decision and land within the confidence tolerance. Disagreement means no payout, and the milestone stays open.

Guarantees

What the contract enforces.

Each guarantee below has at least one dedicated test proving it.

Unambiguous grant identity

Grants are keyed by {owner}_{grant_id}, so two granters can use the same grant name without ever touching each other's state.

No self-resolution

A submitter can never resolve their own milestone. The check runs before the role check, so it cannot be bypassed by holding both roles.

Owner-only role grants

Only a grant's owner may register contributors and reviewers. Lookups for non-owners revert rather than leaking whether a grant exists.

Typed storage only

State lives in TreeMap with @allow_storage dataclasses. No dict or list in storage, no non-deterministic writes outside the equivalence block.

Single-resolution milestones

A resolved milestone cannot be resolved again, so an accepted milestone cannot be replayed to drain a grant's budget.

Consistent welfare state

Acceptance sets the distribution flag and writes the ledger entry under the same composite key, so released funds are always reflected in state.
