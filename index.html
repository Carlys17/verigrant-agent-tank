VeriGrant

Grant milestone verification with consensus: contributors submit evidence, an LLM judge and a re-judging validator must agree, and welfare disburses only on agreement.

Live contract GitHub

The problem

Grant programs everywhere share the same bottleneck: a human reviewer must read milestone evidence and decide whether the work meets the criteria before funds are released. That review is slow, subjective, and unauditable — and it is exactly the judgement call an intelligent contract can make instead.

How it works

A granter creates a grant
Registers budget, contributors, and reviewers. The grant's identity is an unambiguous composite key {owner}_{grant_id}.
A contributor submits evidence
A milestone with target criteria and a live evidence URL — a repo, doc, or post.
A reviewer triggers resolution
resolve_milestone runs a leader function that fetches the evidence from the live web and asks an LLM to judge it against the stated criteria.
The validator re-judges independently
Through the Equivalence Principle, validators re-fetch the evidence and re-run the judgement. The decision stands only if leader and validators agree on the binary outcome and stay within confidence tolerance.
Welfare disburses on consensus
On agreement, the contract releases the milestone's welfare to the contributor — no human in the loop, every decision onchain and auditable.

Why the consensus is real

A validator that always returns True would defeat the purpose. VeriGrant's validator independently re-fetches the evidence and re-runs the judgement, comparing the decision fields (accepted, confidence) rather than free-text reasoning — so it tolerates LLM nondeterminism without letting a rejection flip into an acceptance.

Typed state

TreeMap storage with @allow_storage dataclasses. No dict/list leakage, deterministic milestone-id counter.

Role enforcement

Owner-only role registration, contributor-only submission, reviewer-only resolution. A submitter can never resolve their own milestone.

12 direct tests

Key isolation, permission guards, self-resolve rejection, validator disagreement, and welfare state on accept/reject.

Reusable primitive

Any grant or funding dApp can build on this: the criteria are public, stored onchain, and scored by consensus. Grant programs, bounty platforms, and milestone-based funding all reduce to the same shape — evidence in, judged outcome out, funds released on agreement.
